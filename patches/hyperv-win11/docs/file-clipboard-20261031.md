# 文件与文件夹共享剪贴板（2026-10-31）

本轮已实现 Windows 宿主机与 Hyper-V Win11 虚拟机之间的文件、文件夹双向复制。只支持复制，不移动或删除源文件。原生 Windows Shell 跨机器测试和用户在资源管理器中的双向实测均通过，修正版 Sunshine 已部署，Moonlight 使用独立的 `6.5.3-hdrfix.1-filecopy.1` 目录。

## 使用方式

连接 Moonlight 的 Desktop 后，在一端资源管理器选中文件或文件夹，按 Ctrl+C；切换到另一端的资源管理器目标文件夹，按 Ctrl+V。文件内容在粘贴时读取，进度与重名处理使用 Windows 原生复制界面。包含子目录和空文件夹。

连接前已经复制的文件不会自动导出，请连接后重新复制。断开、锁屏、退出用户或会话切换后，旧文件引用应失效；重新连接并重新复制即可。目的端可能保留 Windows 已经写入的部分文件，源文件始终保留。

上游仍保护目标端尚未粘贴的本地文件复制：此时远端文字或图片可能被忽略。在目标端复制一次文字即可解除该状态。已验证远端虚拟文件列表切换回文字正常；本轮没有取消上游对本地文件的保护。

优先验收资源管理器之间的复制。只接受本地文件路径列表、不能读取 Windows 虚拟文件流的其他应用，不在本轮验收范围内。

## 这轮如何实现

服务端新增当前交互用户权限的文件剪贴板辅助进程，读取该用户主动复制的文件。Sunshine 服务通过只允许 SYSTEM 和该用户访问的本地管道连接它，并核对进程、会话和用户身份；服务本身不以 SYSTEM 权限打开用户选中的文件。

跨机器传输复用 Moonlight 与 Sunshine 已配对的 HTTPS 连接，不增加网络监听端口。文件名清单与读取请求走独立端点，文件内容按最多 1 MiB 分块读取；不会把整份文件装进原来的图片剪贴板缓存。只有证书仍有效、仍配对且正在串流的客户端可以使用对应会话的文件引用。

Moonlight 的必要改动集中在剪贴板辅助程序和文字/图片应用前的衔接信号，不改硬件解码或画面呈现代码。Windows 虚拟文件数据对象通过 FileGroupDescriptorW、FileContents 和 IStream 提供内容，64 位文件大小和读取偏移可跨越 4 GiB。

首版边界：每次最多 20,000 个文件及目录条目，目录深度最多 64 层，传输相对路径必须小于 260 个 UTF-16 单元。拒绝路径越界、设备名、重名冲突、符号链接、目录联接和其他重解析点。源文件的标识、长度或修改时间发生变化时，读取应失败，不悄悄切换到另一份文件。

| Sunshine 0005 | 文件与文件夹剪贴板 | 接收和发送文件清单，按当前用户权限读取文件，通过已配对连接传输。 |

| Moonlight 0003 | Windows 文件剪贴板 | 把另一端的文件呈现给资源管理器，并在粘贴时取回内容；兼顾文件复制与文字、图片剪贴板之间的切换。 |

更新基线时，`main.cpp` 与 `display_vdd.cpp` 中交叉的采集、连续性接入统一放入 Sunshine 0003，避免两份补丁反复触碰同一段上下文。全部补丁从干净上游顺序重放后的文件树，与已构建和验收的文件树完全一致。

这些补丁分别解决已识别的问题，不能据此保证所有黑屏、锁屏或长时间卡屏问题都已根治。先前撤回的客户端自动重连规避补丁不恢复。
