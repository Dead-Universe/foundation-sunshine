# Sunshine 维护补丁

上游基线：`d549e16a3fa0887d26beb98eaa40785c1814b353`。维护源码：`5e832dd884695df3ca2d322cc25cabeeeaaf15c4`，结果树 `5a6744e5e6bbd2b9c5109c2d758861d54f3912dc`。顺序及 SHA256 见 [series.json](series.json)。宿主机上游快照保持干净，源码修改和构建仅在 Win11 虚拟机进行。

| 顺序 | 补丁 | 保留功能 |
| --- | --- | --- |
| 1 | `0001-hyperv-vdd-capture-recovery.patch` | VDD 采集选择、失败诊断、显示恢复、启动唤醒与 Auto 输出恢复 |
| 2 | `0002-nvenc-delayed-completion.patch` | 编码完成事件迟到时有界等待，避免提前销毁未完成帧 |
| 3 | `0003-hyperv-console-continuity.patch` | 服务会话 0 Core、控制台输入与显示辅助进程、会话迁移后采集重建、串流期间显示唤醒保持 |
| 4 | `0004-offline-vbcable-installer.patch` | 捆绑标准 VB-CABLE 原包，保留已有和共享声卡 |

2026-10-30 只修改现有第 3 份补丁。控制台助手原先仅在准备或输入时重置显示空闲计时；无输入串流会使显示进入低功耗，产帧通道消失。输入唤醒虽能产生新通道，旧串流仍可能停在旧资源上。修复在封闭 VDD 串流活动期间保持交互会话的显示请求，停止串流或改用标准采集时释放；连接前的一次唤醒继续保留。没有修改 Moonlight、用户电源方案或登录行为，其余三份补丁字节不变。四份补丁从上游基线独立重放，结果严格等于上述源码树。

验证在虚拟机完成：原生构建及部署版本重建成功，39 项 CTest 零失败，聚合 577 项中 21 项条件跳过。运行版 `2026.1030.212700.5e832dd8` 已可回滚替换并重启，配置及配对保留。修复前的 60 秒显示空闲实验复现了同一帧冻结；修复后相同实验持续 150 秒，超过空闲超时仍有实际运动画面、正常产帧计数，且 182 秒没有远端输入。停止 Desktop 后显示请求释放，原 900 秒交流显示超时恢复。

客户端采用当日最新稳定版 6.5.3 的既有必要维护版 `hdrfix.1`，使用默认 AMD D3D11VA 硬解和独立解码/呈现设备，服务端 NVIDIA HEVC NVENC，协商 1920×1080、144fps。正常入口的首个会话约 11 分 8 秒，实际观察运动画面；窗口/全屏切换、远端开始菜单、两次停止后重连及清理通过，服务 Core 未重启。测试视频自身为 30fps，这不是持续 144fps 性能验收，也不代表全天稳定性已经证明。

VDD 现场驱动另由官方 0.17.2 更新到本基线指定的 0.18.2，恢复了鼠标共享通道，旧驱动已导出备份；驱动升级本身未消除上述空闲冻结，服务端电源请求修复仍然必要。没有改宿主机显卡驱动或证书信任设置。

保留的验证限制：首次命令行自动启动曾停在应用列表加载且未进入 RTSP，正常图形入口重试后可连接；该启动现象尚未归因。增强会话输入密码的登录场景及音频实听本轮未重测。上游后续 `bcbb5ec7` 的两项手柄/增强组件提交已拉取审阅，本次保持 `d549e16a` 基线完成单一故障的前后对照。
